ЗАПУСК
Распакуйте архив целиком и откройте index.html в браузере.
Держите HTML, CSS и JS в одной папке. Для карты и веб-шрифтов нужен интернет.
Для стабильного общего хранилища между страницами рекомендуется локальный сервер:
  python -m http.server 8765
После запуска откройте http://localhost:8765

О ДАННЫХ
Это демонстрация, не реальные GPS-данные. Координаты остановок приблизительны,
линии не привязаны к дорогам. Время в карточках — исходный демонстрационный
прогноз, а обратный отсчёт на карте относится к ускоренной локальной симуляции.
Подбор поездки использует условные маршруты и 3 минуты между остановками.
Избранное и планы сохраняются только в браузере, перевозчику не отправляются.

ВХОД / АВТОРИЗАЦИЯ (auth.js, auth.css, firebase.js)
Вход через Firebase Authentication (проект aqylzhol): Google ИЛИ почта + пароль. Входа по телефону нет.
— Почта + пароль: после регистрации Firebase отправляет письмо со ссылкой подтверждения. Пока ссылка не нажата, на сайт не пускает
  (сессия не создаётся). Окно «Подтвердите почту» само проверяет подтверждение раз в 3 секунды; есть кнопки «Я подтвердил(а)»,
  «Отправить ещё раз» (раз в 60 с) и «Использовать другую почту». Есть сброс пароля («Забыли пароль?»).
— Подтверждение именно ссылкой, а не кодом: код без своего сервера нельзя проверить безопасно. Код потребует Cloud Functions (тариф Blaze).
— В консоли Firebase: Authentication → Sign-in method → включить «Google» и «Email/Password» (обычный, не «Email link»);
  Settings → Authorized domains → ВАШ-НИК.github.io; Templates → язык писем можно сменить на русский.
— firebase.js подключается во всех HTML как <script type="module">. Открывать сайт нужно по http(s): локально
  «python -m http.server 8765» или GitHub Pages. С file:// вход не работает.
— auth.js хранит копию сессии в браузере (aq-auth-session), чтобы кошелёк, роли и уведомления могли синхронно узнать, кто вошёл.
— Главный админ: в начале fleet.js замените ВАШ_АДРЕС@gmail.com в OWNERS на почту владельца (Google или подтверждённая почта с паролем).
ОГРАНИЧЕНИЕ: роли, блокировки, обращения и кошелёк пока лежат в localStorage браузера (db.js), а не в общей базе. Это не защита.

УВЕДОМЛЕНИЯ О ПРИБЛИЖЕНИИ АВТОБУСА (alerts.js, alerts.css)
Настраиваются в помощнике: «Уведомить о автобусе» → автобус → остановка → за сколько минут (1/3/5/10),
или фразой: «предупреди, когда 12 подъедет к вокзалу за 5 мин». Список и отмена: «мои уведомления».
— Срабатывают на любой странице, пока сайт открыт: баннер сверху, звук, вибрация, а при свёрнутой вкладке —
  системное уведомление браузера (после разрешения). Закрытая вкладка уведомлений не присылает: для этого нужен сервер.
— Время берётся из общих часов симуляции AqylSim (enhanced.js, хранятся в браузере): те же часы двигают автобусы
  на карте, поэтому уведомление совпадает с тем, что видно на карте. Скорость демо: ×1 (как в жизни), ×10, ×30 —
  переключается в помощнике и в списке «Скорость» на карте. Пауза на карте часы не останавливает.
— Расписание больше не зависит от загрузки дорог (длина перегона = прямая × 1.3), поэтому ETA одинаков на всех страницах.
— Уведомления привязаны к городу и ждут, пока выбран нужный город.

ВОДИТЕЛИ, АДМИНИСТРАТОРЫ И НОЧНОЙ РЕЖИМ (fleet.js, fleet.css, driver.html, admin.html)
Роли: пассажир (по умолчанию), водитель, администратор. Пункты «Водитель» / «Админ» появляются в меню только у тех, кому они доступны.
— Кабинет водителя (driver.html): большие кнопки «Начал движение», «Стою» (с причиной: остановка, светофор, пробка,
  посадка, перерыв, поломка, ДТП) и «Завершить смену». Видно время до конца рейсов маршрута и свои последние отметки.
  Пассажиры видят отметку на карте, в карточке маршрута и в панели следующей остановки. Пока водитель «стоит»,
  автобус на карте замирает (скорость 0), после «Начал движение» продолжает с того же места.
— Администрирование (admin.html), три вкладки:
  «Люди» — поиск, фильтры, назначить водителем и закрепить автобус, сменить автобус, снять роль,
  сделать/снять администратора, заблокировать/разблокировать. Нельзя заблокировать себя и снять последнего админа.
  «Автобусы» — начало и конец рейсов для каждого маршрута, режим (по расписанию / всегда работает / остановлен),
  принудительная отметка «Стоит / Движется / Сбросить», кнопка «Завершать рейсы в 21:00 на всех маршрутах»,
  тестовое время (например 21:00), чтобы проверить ночной режим без ожидания.
  «Журнал» — последние 100 действий водителей и администраторов.
— Первый администратор: пока админов нет, любой вошедший видит пункт «Админ» и может нажать «Стать администратором».
  Хотите защитить кодом — задайте ADMIN_SETUP_CODE в начале fleet.js.
— Блокировка: заблокированный не может войти (проверка в auth.js), а уже открытый сеанс закрывается в течение секунды.
— Ночной режим: по умолчанию маршруты 14, 30, 12, 5, 21 и 8 заканчивают рейсы в 21:00, 45 и 17 — в 23:00, начало в 06:00.
  Остановленные автобусы скрываются с карты, в карточках маршрутов появляется плашка 🌙, на главной, в маршрутах и на карте —
  баннер «Ночной режим». Время суток берётся с часов устройства. Водителю после конца рейсов отметки недоступны.
Изменения в старых файлах (небольшие): script.js (страницы driver/admin, переход при смене города), brand.js (заголовки),
enhanced.js (две строки статуса на карте), auth.js (запрет входа заблокированным). Во все html добавлены fleet.css и fleet.js.
ОГРАНИЧЕНИЕ: как и аккаунты, роли, блокировки, статусы и расписание хранятся в localStorage одного браузера
(между вкладками и страницами работают, между разными устройствами — нет). Для реальной работы нужен сервер с базой данных
и проверкой прав: иначе любой может открыть консоль браузера и выдать себе роль.


ВЕРСИЯ 8: БАЗА ДАННЫХ, РОЛИ ПО ГОРОДАМ, ТЕХПОДДЕРЖКА
— db.js — простая база данных (AqylDB.table('users'|'roles'|'people'|'tickets'|'log')). Хранится в localStorage браузера.
  Владелец может скачать выгрузку (без паролей): Админ → Журнал → «Скачать базу данных».
— Регистрация: по номеру (+7, код) или по почте + пароль. Имя НЕ обязательно. В базу пишутся id, телефон/почта, город, дата создания и последнего входа.
— Кнопка «Стать администратором» удалена. Главный админ назначается автоматически: если в начале fleet.js задан список OWNERS
  (телефон '77001234567' или почта) — им, иначе первым зарегистрированным аккаунтом. Старые админы из прошлой версии становятся главным админом.
— Роли: главный админ (все города) → админ города → водитель → пассажир.
  Админ города: видит только людей, автобусы, журнал и обращения СВОЕГО города; может назначать водителей, делать других админов
  (только своего города), блокировать обычных людей. НЕ может: снимать админов, блокировать админов, трогать главного админа,
  заходить в управление другим городом, менять тестовое время. Всё это — только главный админ.
  Расписание рейсов теперь хранится отдельно для каждого города.
— Причины остановки «Светофор» и «Пробка» убраны из кабинета водителя (светофоры в физике движения на карте остались).
— Техподдержка: Настройки → «Техподдержка». Сообщение получает админ города пользователя (если его нет — главный админ).
  В меню у админа значок с числом новых обращений; вкладка «Поддержка»: ответить или закрыть. Ответ виден пользователю в Настройках.
ОГРАНИЧЕНИЕ: без сервера всё это работает в пределах одного браузера — обращение дойдёт до админа только если он открыт
в том же браузере. Для настоящей работы между устройствами нужен сервер с базой (db.js рассчитан на замену).

ВЕРСИЯ 11: ОБЩАЯ БАЗА ДАННЫХ (Firebase Firestore) — sync.js, firestore.rules
Теперь аккаунты, «люди», роли, блокировки, обращения в поддержку, расписание, статусы автобусов и журнал общие для всех устройств.
Админ сразу видит новых пользователей (Админ → Люди) и может назначать водителей, админов, блокировать — это работает с другого устройства.
Как устроено: db.js/auth.js/fleet.js по-прежнему пишут в localStorage (как кэш), а sync.js (подключается из firebase.js) зеркалит каждую
запись в Firestore (коллекции db_users, db_people, db_roles, db_tickets, db_sched, db_status, db_log) и подтягивает чужие изменения в реальном времени.
Синхронизация начинается после входа с подтверждённой почтой. Тестовое время админа (aq-fleet-clock) не общее — действует только на его устройстве.
ЧТО СДЕЛАТЬ ОДИН РАЗ:
 1) Firebase Console → Build → Firestore Database → Create database (режим production, регион на выбор).
 2) Firestore Database → Rules → вставить содержимое firestore.rules → Publish. Без этого база закрыта и ничего не синхронизируется.
 3) В firestore.rules (OWNER_EMAIL) и fleet.js (OWNERS) должна стоять одна и та же почта главного админа.
Кто что видит: пассажир — только свои данные; админ города — людей, обращения и журнал своего города; главный админ — всё.
Права проверяются правилами на стороне Firebase, поэтому выдать себе роль через консоль браузера больше нельзя.
При первом открытии этой версии локальные данные браузера очищаются (DB_VERSION=11), вход восстанавливается из Firebase.

Ограничения (честно)
  • Автобусы в проекте — симуляция, поэтому «рядом с автобусом» проверяется на вымышленных позициях. Для проверки в
    Настройках есть демо-режим «поставить меня рядом с автобусом №…». Для реальных автобусов нужны GPS-трекеры.
  • Браузер сам спрашивает разрешение на геопозицию — «включить по умолчанию» невозможно; уведомления включены по умолчанию.
  • Лимит 3 часа и фильтр ников работают в браузере; для полной защиты от обхода нужен серверный код (Cloud Functions).
  • Языки: переведены меню, настройки, кошелёк, вход, FAQ и новые экраны. Непереведённое остаётся по-русски; казахские и
    английские тексты стоит проверить носителем (словарь — в i18n.js).
  • Банковская карта — только тест, реальные платежи не проводятся.

   После выбора ID закрепляется навсегда и не меняется при смене имени. Диспетчеры и разработчик ищут людей по ID; разработчик
   вкладка «User ID» → «Выдать ID всем без ID».
